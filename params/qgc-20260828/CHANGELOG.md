# 파라미터 변경 이력 — ArduCopter 3.6.12 / Pixhawk PX4v3 (Quad X)

기준 스냅샷: `NEWVEHICLE_baseline.params` (2026-08-28, 838개 전량, **변경 전** 상태)

## 2026-08-28 — 배터리 모니터 핀 활성화

| 파라미터 | 변경 전 | 변경 후 | 타입 |
|---|---|---|---|
| `BATT_VOLT_PIN` | -1 (비활성) | **2** | INT8 |
| `BATT_CURR_PIN` | -1 (비활성) | **3** | INT8 |

**이유:** `BATT_MONITOR=4`(전압+전류)로 설정돼 있었으나 두 ADC 핀이 -1이라 측정이
전혀 이뤄지지 않았음. 배터리를 연결해도 전압이 0V로 고정되어 `BATT_LOW_VOLT=14.4`,
`BATT_CRT_VOLT=14.0` 임계값이 절대 발동하지 않는 상태였음.
2, 3은 Pixhawk 1(`BRD_TYPE=2`) 파워모듈 표준 ADC 핀.

**검증:** 변경 후 전압 판독이 0.000V(죽은 값) → 0.511~0.573V 변동(ADC 노이즈),
전류 0.070A. 파워모듈 미연결 상태에서 아날로그 핀이 살아있을 때 나타나는 값.
`SYS_STATUS`의 BATTERY 센서 present/health 모두 True. 재부팅 불필요
(ArduPilot이 read 주기마다 핀을 재적용).

**미검증:** 실제 전압 정확도는 배터리/파워모듈 연결 후 멀티미터 대조 필요.
`BATT_VOLT_MULT=10.1010`, `BATT_AMP_PERVLT=18.0018`은 기존 값 유지(임의 변경 안 함).

## 미해결 — 배터리 failsafe 동작 없음

`BATT_FS_LOW_ACT=0`, `BATT_FS_CRT_ACT=0` (둘 다 None).
이제 전압은 측정되지만 저전압/위험전압 시 **경고만 뜨고 아무 동작도 하지 않음.**
비행 동작에 관한 결정이라 임의 변경하지 않음.

## 2026-08-28 — 전압 멀티플라이어 보정

| 파라미터 | 변경 전 | 변경 후 |
|---|---|---|
| `BATT_FS_LOW_ACT` | 0 (None) | **2** (RTL) |
| `BATT_FS_CRT_ACT` | 0 (None) | **1** (Land) |
| `BATT_VOLT_MULT` | 10.1010 | **10.8199** |

**멀티플라이어 보정 이유:** 핀 활성화 후 FC가 14.05V로 판독했으나 멀티미터 실측은
15.05V. **6.6% 낮게** 읽고 있었음. 표준값 10.1010이 이 파워모듈에 맞지 않았음.
보정식: `10.1010 x (15.05 / 14.05) = 10.8199`

**검증:** 보정 후 판독 15.04V (13샘플, 15.01~15.07). 실측 대비 오차 **-0.01V (0.1%)**.

**중요:** 보정 전에는 실제 15.05V(3.76V/셀, 정상 보관전압)를 14.05V(3.51V/셀)로 읽어
방전 상태로 오인했음. 이 상태로 비행했다면 정상 배터리에서 저전압 failsafe가
조기 발동했을 것. `BATT_LOW_VOLT=14.4`는 이제 실제 3.60V/셀에 해당하여 적정.

`BATT_CRT_TIMER`는 이 펌웨어에 없음(위험전압 즉시 발동). `BATT_LOW_TIMER=10`초.

## 2026-08-28 — 모터 매핑 실측 (프로펠러 제거 상태, MOT_TEST 5% / 2초)

**ESC·모터·Pixhawk 모두 기존 기체와 다른 하드웨어이므로 표준 가정 금지.**
아래는 MOT_TEST 구동 + 육안 확인으로 얻은 실측값이다.

| MOT_TEST 번호 | 출력 채널 | 물리 암 위치 |
|---|---|---|
| Motor 1 | SERVO1 | 우전 (RF) |
| Motor 2 | SERVO4 | 우후 (RB) |
| Motor 3 | SERVO2 | 좌후 (LB) |
| Motor 4 | SERVO3 | 좌전 (LF) |

번호 순서 1->2->3->4 = 우전->우후->좌후->좌전 = **시계방향**. ArduCopter가
기대하는 순서와 부합.

주의: MOT_TEST 번호와 SERVO 출력 채널은 원래 일치하지 않는다
(Motor2->SERVO4, Motor3->SERVO2, Motor4->SERVO3). 'Motor N = SERVO N' 가정 금지.

**결과:** 4개 모터 전부 구동 확인(육안). 채널 크로스토크 없음 - 각 테스트에서
해당 채널만 982->1033us 상승, 나머지 3채널 982us 유지.
전압 강하 최대 0.09V (15.05V 시작), 매우 안정적.

**미검증:** 각 모터의 회전 방향(CW/CCW). MAVLink로는 확인 불가하며 육안 확인 필요.
Quad X 규격: 우전(RF)/좌후(LB)=CCW, 좌전(LF)/우후(RB)=CW.

|---|---|---|---|---|
| Motor 1 | 우전 (RF) | CW | CCW | **반전 필요** |
| Motor 2 | 우후 (RB) | CW | CW | 정상 |
| Motor 3 | 좌후 (LB) | CW | CCW | **반전 필요** |

**조치:** Motor 1(우전)과 Motor 3(좌후) — 대각선 한 쌍 — 의 바나나잭 배선 반전.
모터 3선 중 임의의 2선을 서로 바꾸면 회전 방향이 반전됨.
작업 시 배터리 분리 필수.

**주의:** ESC/모터/Pixhawk 모두 기존 기체와 다른 하드웨어. 기존 기체의
배선 순서나 tools/verdict.py 의 PX4 기준 매핑을 참조하지 말 것.

**미완료:** 배선 작업 후 Motor 1, 3 재확인 필요.

## 2026-08-28 — ESC 캘리브레이션 및 PWM 범위 정리

| 파라미터 | 변경 전 | 변경 후 |
|---|---|---|
| `MOT_PWM_MIN` | 0 | **1000** |
| `MOT_PWM_MAX` | 0 | **2000** |
| `ESC_CALIBRATION` | 0 | 3 (설정 후 재부팅, ArduPilot이 자동 0으로 리셋) |

**PWM 범위 명시 이유:** MIN/MAX가 0이면 ArduPilot이 `RC3_MIN/MAX`(982~2005)를
모터 출력 범위로 사용하는데, `SERVO1-4_MIN/MAX`는 1100~1900이라 서로 불일치했음.
1000/2000으로 명시해 RC 입력 범위와 모터 출력 범위를 분리.

**검증:** MOT_TEST 출력 대비 PWM이 새 범위를 정확히 추종.
5%=1050us, 10%=1100us, 15%=1150us (변경 전에는 5%에서 1033us).

**ESC 캘리브레이션 절차:** ESC_CALIBRATION=3 -> 재부팅 -> 안전 스위치 길게 누름
-> ESC가 최대/최소 스로틀 학습. 사용자 확인: LED 깜빡임 -> 길게 누름 -> 빨간색
유지, 이후 모터 자동 회전 관측됨. 완료 후 전원 재인가로 정상 부팅 확인.

**미확정:** 4개 ESC의 학습값 일치 여부. 무부하(프로펠러 제거) 상태에서는 전류가
0.1A대에 불과해 편차(0.01~0.05A)에 판별력이 없음. MAVLink로는 개별 ESC 학습값을
읽을 수 없으므로 회전음 청취 또는 실부하 테스트로만 확인 가능.

### 이번 세션에서 겪은 함정 (재발 방지)

1. **재부팅 시 포트 번호 변경** — ttyACM0 -> ttyACM1 -> ttyACM0.
   `mav.find_port()` 로 자동 탐색하도록 수정. `MAV_PORT` 환경변수로 강제 지정 가능.

2. **재부팅 시 MAVLink 스트림 구독 소실** — ArduPilot은 GCS가
   REQUEST_DATA_STREAM(66)을 보내야 SYS_STATUS/SERVO_OUTPUT_RAW 등을 전송한다.
   그전까지는 QGC가 켜둔 스트림에 무임승차하고 있었음. 재부팅 후 HEARTBEAT만 오고
   전압/서보출력이 0으로 보여 "배터리 미연결"로 오진했음.
   `Mav.request_streams()` 추가, 전 도구에서 연결 직후 호출.

3. **ESC 캘리브레이션 대기 중에는 HEARTBEAT가 나오지 않음** —
   `Initialising APM` 만 반복. FC 고장이 아니라 안전 스위치 대기 상태.

4. **조종기 전원 OFF 시 `PreArm: Throttle below Failsafe`** 는 정상.
   MOT_TEST 는 RC와 무관하게 동작하므로 조종기 없이 모터 테스트 가능.

## 2026-08-28 — RC ARM 및 스로틀 제어 테스트 (프로펠러 제거 상태)

**결과: 성공.** 파라미터 변경 없이 조종기만으로 진행.

### ARM 절차 확인
- CH5(비행모드 스위치) 최상단 = PWM 2005 -> STABILIZE
- 스로틀 최하(982) + 요(CH4) 우측 끝(2002) 약 2초 유지 -> ARM
- PreArm 경고 없음. 전 항목 통과.

### 스로틀 -> 모터 연동
스로틀 982 -> 1458 상승 시 SERVO 출력 1000 -> 1435 비례 추종.
4채널 균일하게 반응. 최대 도달값 SERVO1-4 = 1572/1574/1554/1572 us.

### 자세 제어(STABILIZE) 동작 확인
스로틀 유지 중 4채널 출력이 분화되는 것을 관측:
  [1543, 1221, 1150, 1566]  <- 우측(SERVO1=M1우전, SERVO4=M2우후) 상승
  [1150, 1574, 1152, 1569]  <- 좌측 상승
이는 FC가 자세를 수평 유지하려 모터별 출력을 조절하는 정상 동작.
자이로/가속도계/믹서 정상 작동 확인. 대각선 쌍 연동 패턴도 규격 부합.

### 확인된 ARM 조건 (실측)
- MOTOR_OUTPUTS enabled=True (안전 스위치 해제 완료)
- 비정상 센서 없음, 배터리 14.90V
- GPS 없음(실내)이지만 STABILIZE는 GPS 불필요하므로 ARM 가능
- ARMING_RUDDER=2 이므로 요 스틱 ARM 방식 사용 가능

**주의:** DISARM 은 스로틀 최하 + 요 좌측 끝 유지.

## 2026-08-28 — 킬 스위치(Motor Emergency Stop) 할당 및 검증

| 파라미터 | 변경 전 | 변경 후 |
|---|---|---|
| `CH7_OPT` | 0 (Do Nothing) | **31 (Motor Emergency Stop)** |

### 조종기 측 (TX16S, 사용자 수동 설정)
- SF 2단 스위치 -> **CH7** (처음 CH6에 할당했다가 이동)
- 실측 PWM: **킬 OFF(안전) = 982 / 킬 ON(정지) = 2005**
- ArduPilot 발동 임계값 1800 을 충분히 초과

**주의 — CH6 는 킬 스위치로 쓸 수 없다:** ArduCopter 3.6 에는 `CH6_OPT` 파라미터가
존재하지 않는다. 보조 기능은 `CH7_OPT` 부터만 지원되며, CH6 는 튜닝 노브 전용으로
예약되어 있다(`TUNE`, `TUNE_LOW`, `TUNE_HIGH` 와 연동). 처음 CH6 에 할당했다가
`CH6_OPT` 읽기 실패로 발견해 CH7 로 옮겼다.

### 동작 검증 (프로펠러 제거, ARM 상태, 배터리 14.89V)
```
[3.5s] 킬 ON  (CH7=2005)
[3.6s] SERVO [1000,1000,1000,1000]  <- 0.1초 만에 4채널 전부 정지
[4.4s] 킬 OFF (CH7=982)
[4.5s] SERVO [1068,...]             <- 즉시 회전 재개
[5.2s] SERVO [1000,1000,1000,1000]  <- 2회차도 즉시 정지
```
킬 직전 SERVO 최대 1209 -> 킬 중 1000. **2회 반복 모두 정상 작동.**
응답 시간 약 0.1초.

**killtest.py 판정 버그 수정:** 판정 구간을 "킬 ON 후 3초"로 잡아, 사용자가 킬을
OFF 로 되돌린 뒤의 회전값(1215)까지 포함해 "출력이 남아있다"고 오판했다.
킬이 **유지되는 구간**(다음 킬 OFF 전까지)만 보도록 수정.

## E. 캘리브레이션

순서를 지킨다. 앞 단계가 뒤 단계의 전제다.

- [ ] **가속도계** — 6면 전부. 평평한 곳에서, 기체를 흔들지 않고
- [ ] **자기계(나침반)** — 🔴 **야외에서.** 실내는 철근·전자기기 때문에 오염된다
  - [x] ✅ 구성 정리 완료 (2026-09-14): `COMPASS_USE3` 1→0
  - 현재 구성 (GPS 1개):
    - 슬롯1 = GPS 모듈 내장, `EXTERNAL=1`, `USE=1` → **주 나침반**
    - 슬롯2 = FC 내장, `USE=0` → 의도적 미사용 (전원선·ESC 간섭 회피)
    - 슬롯3 = 없음, `USE=0`
  - [ ] 🟠 **오프셋 재보정 필요** — 슬롯1 크기 101.9 (통상 100 미만 권장).
        분해·재조립으로 배치가 달라졌으므로 어차피 다시 잡아야 한다
  - [ ] 오프셋이 비정상적으로 크면 GPS 마스트를 더 띄운다
  - ⚠️ 나침반이 안 잡히면 **GPS 케이블 접촉부터 확인**한다.
        AK09916 은 GPS 모듈 안에 있다 ([함정 기록](00-progress.md#-오늘-겪은-함정--반복하지-말-것))
- [ ] 🔴 **송신기 바인딩** — 2026-09-14 현재 **미완. 여기서 막혀 있다**
  - 수신기는 **RC 포트**에 연결됨, FC 가 인식함 (`chancount=16`)
  - 그러나 CH1~8 전부 0, `rssi=0` → 송신기와 바인딩 안 됨
  - ⚠️ ArduCopter 3.6.12 에는 `RC_PROTOCOLS` 가 **없다**.
    Pixhawk 2.4.8 의 전용 `RC` 포트가 PPM/SBUS 를 자동 감지한다
  - ⚠️ `SB` 는 **출력** 전용(`BRD_SBUS_OUT=0`), `SPKTRM/DSM` 은 스펙트럼 전용(3.3 V)
- [ ] **RC 송신기 캘리브레이션** — 전 채널 min/max/trim
  - [ ] 이전 값 참고: MIN 982 / MAX 2005 / TRIM 1494
  - 🔶 982~2005 범위는 **SBUS** 의 전형값. 보정된 채널이 5개뿐 → **5채널**로 쓰던 기체
- [ ] **ESC 스로틀 범위** — 🔴 **프롭 분리 상태에서** 4개 동시
- [ ] **전압·전류 센서** — 멀티미터 실측과 대조해 `BATT_VOLT_MULT`, `BATT_AMP_PERVLT` 보정
  - [ ] 이전 값: 10.8199 / 18.0018 — **PM 이 바뀌었으면 무효**

## G. 🔴 배터리 Failsafe — 반드시 고친다

**현재 값은 잘못돼 있다.** 로그 8·9·10 에서 failsafe 가 계속 터져 시험이 중단됐다.

| 파라미터 | 현재(잘못) | 권장 | 근거 |
|---|---|---|---|
| `BATT_LOW_VOLT` | 🔴 14.4 V | **14.0 V** | 3.5 V/셀 — 부하 상태 4S |
| `BATT_CRT_VOLT` | 🔴 14.0 V | **13.2 V** | 3.3 V/셀 |
| `BATT_CAPACITY` | 2900 | 2900 | ✅ 보유 배터리와 일치 |
| `BATT_LOW_MAH` | — | **2030** | 용량의 70 % |
| `BATT_CRT_MAH` | — | **2320** | 용량의 80 % (DoD 상한) |
| `BATT_FS_LOW_ACT` | 2 (RTL) | 2 (RTL) | ✅ |
| `BATT_FS_CRT_ACT` | 1 (LAND) | 1 (LAND) | ✅ |

⚠️ low 와 critical 사이에 **최소 0.8 V 이상** 간격을 둔다.
현재는 0.4 V 라 사실상 동시에 터진다.

- [ ] 위 값으로 재설정

## 🔴 이 프로젝트의 현실 — 처음 오는 사람이 먼저 읽을 것

### 1. 신규 제작이 아니다. 분해 후 재조립이다

**기존에 날던 쿼드를 분해했다가 다시 조립하는 작업**이다.
부품이 새것이 아니고, FC 에는 이전 기체의 설정이 그대로 남아 있다.

그래서 이 저장소에는 두 종류의 값이 섞여 있다:

| 종류 | 신뢰도 | 예 |
|---|---|---|
| 이전 기체의 잔재 | 🔶 **검증 안 됨** | `MOT_THST_HOVER=0.540`, PID, 나침반 오프셋 |
| 이 기체에서 실측 | ✅ 믿을 수 있음 | 펌웨어 버전, 출력 매핑, 센서 검출 결과 |

🔴 **잔재를 실측처럼 쓰지 마라.** 프레임·프롭이 바뀌면 추력·PID 는 전부 무효다.

### 2. 스택이 문서 전제와 다르다

README 는 PX4 를 전제로 시작했으나, **실물 FC 에는 ArduCopter 3.6.12** 가
올라가 있다. 아직 바꿀지 유지할지 결정하지 않았다.
→ [절차 02 A항](02-fc-setup.md)

### 3. 실비행 이력이 없다

SD 카드에 로그 10개가 있으나 **전부 실내 지상시험**이다
(GPS fix 0, 최고고도 1.51 m). 야외 비행 기록은 0건이다.

다만 `MOT_HOVER_LEARN=2` (호버추력 자동학습)가 켜져 있고
`MOT_THST_HOVER=0.540` 이 학습된 값으로 보이므로,
**SD 카드에 남지 않은 과거 비행이 있었을 가능성**이 있다.

## 🔴 미해결 — 다음에 이어서 할 것

### 1. 🔴 MAIN4 모터가 "QGC All" 에서만 안 돈다

**증상:** 개별 테스트로는 돌지만, QGC 의 All(4개 동시) 에서는 그 모터만 안 돈다.

**확인된 것:**
- ✅ FC 신호 출력은 정상 (개별·순차 전체 모두 MAIN4 에 1150 나감)
- → **FC 설정 문제가 아니다.** ESC·전원·모터 구간의 문제다

**유력한 원인 (미검증):**

| 가설 | 근거 | 확인 방법 |
|---|---|---|
| **동시 기동 전압강하** | 4개 동시 기동 전류 → 순간 강하 → 가장 취약한 ESC 가 기동 실패 | 4개 동시 기동하며 전압 로그 관찰 |
| ESC 개체 불량 | 개체차(커패시터·부트시간) | **신호선만 다른 포트로 옮겨 증상이 따라가는지** |
| 전원 배선 접촉저항 | 그 ESC 납땜만 부실 | 육안·멀티미터 |
| ESC 캘리브레이션 미완 | 4개 스로틀 하한 제각각 | 캘리브레이션 후 재시험 |

🔶 **전류 측정값이 이상하다.** 15 % 스로틀에서 총 0.15~0.19 A 만 측정됐다.
3508 모터 4개가 실제로 돌면 이보다 훨씬 커야 한다. 둘 중 하나다:
- 모터가 실제로는 안 돌았다
- `BATT_AMP_PERVLT=18.0` 전류센서 보정이 틀렸다

→ **다음 세션에서 가장 먼저 풀 것.**

### 2. 🔴 송신기 바인딩 안 됨

```
chancount = 16   ← 수신기는 인식됨
CH1~8 = 0        ← 채널 데이터 없음
rssi = 0
```

수신기는 **RC 포트**에 연결됐고 FC 가 인식한다. 송신기 바인딩만 남았다.

⚠️ ArduCopter 3.6.12 에는 `RC_PROTOCOLS` 파라미터가 없다.
Pixhawk 2.4.8 의 **전용 `RC` 포트**로 PPM/SBUS 를 자동 감지한다.
- `SB` 는 **출력** 전용 (`BRD_SBUS_OUT=0`)
- `SPKTRM/DSM` 은 스펙트럼 위성수신기 전용(3.3 V)

RC1~5 캘리브레이션 값이 982~2005 → **SBUS 수신기**로 쓰던 흔적.
보정된 채널이 5개뿐 → 실제 사용은 **5채널**.

### 3. 🔴 ESC 캘리브레이션 — 바인딩 후에만 가능

**스로틀 입력이 필수**라 송신기 바인딩 전에는 성립하지 않는다.
→ 절차는 [절차 03 지상시험](03-ground-test.md) 참조

### 4. 🔴 배터리 failsafe 임계가 4S 에 맞지 않는다

| 파라미터 | 현재 | 권장 | 근거 |
|---|---|---|---|
| `BATT_LOW_VOLT` | 🔴 14.4 V | **14.0 V** | 3.5 V/셀 |
| `BATT_CRT_VOLT` | 🔴 14.0 V | **13.2 V** | 3.3 V/셀 |

low 와 critical 간격이 0.4 V 뿐이라 사실상 동시에 터진다.
**SD 로그 8·9·10 에서 지상시험이 계속 중단된 원인이 이것이다.**
→ 아직 **수정하지 않았다.**

## 📋 작업 수칙 — FC USB 는 한 프로그램만

라이브 화면 `drone-live`(`localhost:4410`)와 웹 푸시 `drone-livepush` 는 rim3 의 systemd user 유닛이다.

🔴 **포트는 하나다.** loglist·logdl·preflight·QGC 로 직접 붙으려면 먼저 내린다.

(QGC 가 쥐고 있는 경우도 있다).


`usb-3D_Robotics_PX4_FMU_v2.x_*` (`26ac:0011`) 가 이 기체(Pixhawk 2.4.8)다.

## 🔴 오늘 겪은 함정 — 반복하지 말 것

### 0. 재생 화면이 「값이 안 변한다」— 원인은 dict 하나 (2026-09-17)

로그를 고르면 파일명·진행바는 뜨는데 계기가 라이브 값에서 안 움직였다.
서버 응답은 내내 정상이었고 요청도 200 이었다 — 그래서 서버만 봐서는 못 찾았다.

원인: `/api/playback/series` 의 `cols` 에 모터를 **dict** 로 넣었다.
프론트는 `for (const k in s.cols) trk[k] = s.cols[k].slice(...)` 로 도는데
dict 에는 `.slice` 가 없다. `TypeError` 가 `pbFillCharts()` 에서 나고,
그 호출이 `render(s)` **앞**에 있어 화면을 통째로 못 그렸다.
`try/catch` 가 조용히 삼켜 콘솔에도 안 떴다.

🔴 **`cols` 의 값은 반드시 리스트다.** 하나라도 아니면 화면 전체가 죽는다.

진단은 `DRONE_LIVE_DEBUG=1` 로 `/api/*` 요청을 찍어서야 풀렸다 —
프론트가 실제로 무엇을 부르는지 봐야 했다.

⚠️ 곁가지로 배운 것: 진단하느라 `curl .../playback/close` 를 부르거나
서버를 재시작하면 **브라우저는 그 사실을 모른 채** 재생 상태로 남는다.
같은 증상으로 보여 두 번 헤맸다.


### 1. 재부팅만 했는데 ESC 캘리브레이션 모드에 들어갔다

수신기가 유효 신호를 못 주는 상태에서 FC 를 재부팅했더니:

```
ESC calibration: Auto calibration
ESC calibration: Push safety switch
```

**`ESC_CALIBRATION` 파라미터는 `0` 그대로였다.** 휘발성 모드다.
ArduCopter 는 **부팅 시 스로틀이 최대로 읽히면 자동으로** 이 모드에 진입한다.

🔴 **프롭이 달린 상태에서 이 모드에 들어간 뒤 안전스위치를 누르면 모터가 돈다.**
- 탈출: 안전스위치를 누르지 말고 **전원을 껐다 켠다**
- 예방: 재부팅 전 **스로틀 입력이 정상인지 확인**한다

### 2. GPS 케이블 접촉 불량

부팅 시 `AK09916: Reset Failed` 가 떴고, `COMPASS_EXTERNAL` 이 0 으로,
`COMPASS_DEV_ID2` 가 사라진 것처럼 보였다.
**GPS 케이블을 다시 연결하니 전부 정상화**됐다.

→ 나침반이 이상하면 **GPS 모듈 케이블부터 확인**한다.
AK09916 은 GPS 모듈 안에 들어있는 나침반이다.

### 3. 진단 스크립트 자체의 버그에 속지 말 것

나침반 조회 중 `COMPASS_EXTERNAL` 이 1→0 으로 바뀐 것처럼 보였으나,
**FC 값은 변한 적이 없었다.** 파라미터명 조립 로직의 버그였다:

- 슬롯1 = `COMPASS_EXTERNAL` (접미사 없음)
- 슬롯2 = `COMPASS_EXTERN2`
- 슬롯3 = `COMPASS_EXTERN3`

접미사를 기계적으로 붙이면 슬롯1을 못 읽고 0 으로 보인다.

🔴 **값이 바뀐 것 같으면, 바꾼 적이 있는지부터 확인한다.**
도구가 틀렸을 가능성을 먼저 의심한다.

### 4. MAVLink 모터 테스트 명령의 "전체" 파라미터

`MAV_CMD_DO_MOTOR_TEST` 에 `param1=0, param5=4` 로 보내면
ArduCopter 3.6.12 에서 **전체로 해석되지 않고 첫 모터만 돈다.**

올바른 순차 전체 호출:
```
param1 = 1   (시작 모터)
param2 = 0   (throttle type: percent)
param3 = 15  (스로틀 %)
param4 = 3   (각 모터 지속 초)
param5 = 4   (모터 수)
param6 = 1   (test order: SEQUENCE)
```

⚠️ 이 잘못된 호출 때문에 "MAIN2/3/4 가 전체 테스트에서 안 나온다"는
**오진을 할 뻔했다.** 명령이 제대로 갔는지 `COMMAND_ACK` 로 확인할 것.

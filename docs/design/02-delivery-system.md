# 설계 02 — 교내 배송 체계

DRONE01 을 교내 근거리 배송 드론으로 쓰는 설계. 사람이 웹·앱으로 드론을 부르면
기지에서 자동이륙해 그 지점에 내려앉고, 짐을 실어 목적지를 고르면 그리로 날아가며,
받는 사람이 수거완료를 누르면 기지로 돌아온다.

작성 2026-10-07. 이번에 만든 것은 **웹 배송 탭과 서버 상태머신까지**다. 기체로 명령을
보내는 경로는 아직 없다 (§3, §8).

## 1. 체계

```
 사람 (웹 drone01.shade-signals.com 콕핏 배송 탭, 앱은 같은 화면을 WebView 로)
   │ HTTPS
   ▼
 drone01 서버 (web/server.js + web/delivery.js)
   - 학교 계정 대리 로그인, 배송 상태머신, 지점 목록
   - /api/live/* 실시간 상태 (지금 있는 것)
   ▲            ▲
   │ 폴링(일감) │ push(텔레메트리)
   │            │
 Pi (기체 탑재, LTE) ─── USB/TELEM ─── FC (ArduCopter)
```

- **명령은 Pi 가 서버를 폴링해 가져간다.** LTE 는 사업자 NAT 뒤라 서버가 기체로 접속할 수 없다.
  `GET /api/delivery/job` (키 필요)이 지금 구간의 출발·도착 좌표를 준다 — 응답 모양은 이번에 고정했다
- **텔레메트리는 지금 경로를 Pi 로 옮기면 된다.** `tools/live/drone_live.py` + `web/live/livepush.py`
  는 한 방향(올리기만)이라 들어오는 포트가 필요 없다
- 🔴 지금 웹은 기체로 아무것도 못 보낸다(server.js 라이브 절 주석). Pi 가 미션을 실행하기
  시작하면 이 원칙이 바뀐다 — 그때 이 문서와 server.js 주석을 같이 고친다

## 2. 배송 상태머신

서버(`web/delivery.js`)가 정본이다. 화면은 서버가 준 `can` 의 버튼만 그린다.
기체 1대 → 진행 중 배송 1건. 대기열은 없다(진행 중이면 새 호출은 409).

상태 = 구간 `leg`(pickup 픽업 · dest 목적지 · home 복귀) × 단계 `phase`(wait 대기 · fly 비행 · landed 착륙).

| 현재 | 동작 | 다음 | 누가 |
|---|---|---|---|
| 없음 | 호출(지점) | pickup/wait | 로그인 사용자 — 운행 켜짐 |
| \*/wait | 출발 | \*/fly | 기체 (`X-Delivery-Key`) |
| \*/fly | 착륙 | \*/landed | 기체 |
| pickup/landed | 보내기(지점 — 기지도 된다: 복귀) | dest/wait | 요청자 |
| dest/landed | 수거완료 | home/wait | 로그인한 누구나 (받는 사람은 정하지 않는다 — 학번 인증이 곧 자격) |
| home/landed | (자동) | 끝 | — |
| pickup/wait | 취소 | 끝 | 요청자 |
| pickup/fly·landed | 취소 | home 구간으로 | 요청자 |
| 착륙 후 대기 초과 | (서버) | home/wait + 미배송 표시 | 서버 |

- 화면 상태는 셋 — **사용 중**(배송 진행), **대기 중**(호출 없음 + 링크 12초 안 + GPS 3D fix + 전압 14.0 V 이상 — 00-progress #4 권장 저전압),
  **사용 불가**(그 밖, 링크 미연결 포함). 호출은 대기 중일 때만 된다. 배터리 % 는 쓰지 않는다(3.6.12 는 배터리를 떼도 99 %, 2026-09-21 실측)
- 사용자 = 호출한 사람 「이름 (학번)」, 접속한 누구에게나 보인다(내부 공유 드론, 2026-10-07 결정). 이름은 학교 상단 인사(Top.aspx)에서 읽어 쿠키와 그 배송에만 남긴다
- 대기 시간 기본값 픽업 5 분 · 목적지 10 분 — **운영값이지 측정값이 아니다**. `.env` 의 `PICKUP_WAIT`·`DEST_WAIT`
- **관리자 계정·관리자 화면은 두지 않는다 (2026-10-07 결정).** 처음엔 관리자가 지점을 지도로 찍고 출발·착륙·운행을
  눌렀으나, 지점과 운행은 소스·설정으로만 바꾸기로 했다. 지점·좌표·기지는 `web/delivery.js` 의 `CATALOG`
- 기체 쪽 전이(출발·착륙)는 `X-Delivery-Key` 로만 — 지금은 수동 배송 때 키로 부르고, 나중에 Pi 가 부른다
- 운행(실제 배송 접수)은 랩서버 `.env` 의 `DELIVERY_SERVICE=on`, 기본 꺼짐. 조종사가 없을 때 호출을 받지 않기 위해서다.
  테스트 탭은 브라우저 안 시뮬레이터라 운행과 무관하다
- 모든 전이는 `DATA_DIR/delivery-log.jsonl` 에 누가·언제 남는다

## 3. 미션 꼴 (P3 에서 만든다 — 아직 없음)

구간마다 미션 하나:

```
seq 0  홈 (ArduPilot 규칙 — 0번은 홈으로 덮인다)
seq 1  TAKEOFF   순항고도
seq 2  WAYPOINT  목적지, 순항고도
seq 3  LAND      목적지
```

- 복귀도 같은 꼴로 기지행 미션을 올린다. `RTL` 을 쓰지 않는 이유: `RTL_ALT` 는 기체 전역값(지금 1500 = 15 m,
  params 09-21)이라 구간별 고도를 못 준다
- 업로드는 SHADE01 `tools/fc/mission_push.py`(업로드 후 되읽어 대조)를 ArduPilot 규칙으로 고쳐 쓴다 — 그건 PX4 용이다
- 🔶 ArduCopter 3.6.12 에는 `AUTO_OPTIONS` 가 없다. AUTO 로 바로 ARM 이 되는지, LAND 후 자동 disarm 다음에
  재이륙을 어떻게 잇는지는 **같은 펌웨어 SITL 로 먼저 확인**한다. 펌웨어를 바꿀지([06](../procedures/06-px4-migration.md))도 이때 정한다
- 지금 FC: `MIS_TOTAL=0`, `FENCE_ENABLE=0`, `GRIP_ENABLE=0`, `FLTMODE` 에 AUTO·RTL·LAND 없음, `WPNAV_SPEED=500` (params 09-21)

## 4. 고도 정책

지형지물을 계산하지 않고 **충분히 높이 올라가 직선**으로 간다.

- 고도는 **수동 배송 비행 로그**에서 구간별로 정한다: 그 구간 수동 비행의 최대 통과 고도 + 여유
- 수동 배송 때도 웹 배송 탭으로 접수·진행한다 → 어느 비행이 어느 구간인지 `delivery-log.jsonl` 과 `.BIN` 로그 시각으로 짝지을 수 있다
- 🔶 데이터가 생기기 전에는 순항고도 숫자를 정하지 않는다
- 지점은 고정 6곳 — 본관·대운동장(기지)·화영운동장·공학관·한마관·도서관. 좌표는 사용자 제공(2026-10-07)이고
  기체 GPS 실측이 아니다. 🔶 자동비행(P3) 전에 기체를 각 지점에 두고 실측해 `CATALOG` 를 바꾼다

## 6. 인증 — 학교 계정 대리 로그인

경남대 수강신청(sugang.kyungnam.ac.kr)은 SSO·OAuth 가 없고 ASP.NET 폼 하나다
(`txtUserID`, `txtPassword`, `__VIEWSTATE`, EUC-KR — 2026-10-07 실측). 그래서 서버가
사용자의 학번·비밀번호를 학교에 **한 번 대신 제출**해 성공 여부만 보고, 성공하면 자체 쿠키를 준다.

- 비밀번호는 저장·기록하지 않는다. 쿠키는 서명만 된 `__Host-dlv`(12 시간) — 서버에 세션 파일 없음
- 시도 제한: 아이디당 실패 3 회 / 15 분, 전역 30 회 / 10 분, 학교 요청 동시 1 개 — 학교 계정 잠금 기준을 몰라 보수적으로
- **성공 신호 — 2026-10-07 실계정 실측** (`tools/delivery/sugang_probe.js`): 맞든 틀리든 POST 는 200 이고
  로그인 폼이 다시 나온다. 리다이렉트는 없다. 갈리는 것은 쿠키다 — 맞으면 `ASP.NET_SessionId`·**`.ASPXAUTH`**
  발급, 틀리면 쿠키 없음 + alert "사용자 비밀번호가 일치하지 않습니다.". `judge()` 는 `.ASPXAUTH` 가 있어야만
  성공이다. 처음 설계의 "302 = 성공" 가정은 틀렸다
- 운영 로그인은 랩서버 `.env` 에 `SUGANG_URL` 을 넣어야 열린다(비우면 503)
- 🔶 위험 — 학교 비밀번호가 우리 서버를 거친다. **학교 측 허락과 개인정보 처리 고지**가 필요한지 확인한다.
  우리 로그인 때문에 사용자의 수강신청 세션이 끊길 수 있다(로그아웃 주소를 알면 `SUGANG_LOGOUT` 으로 바로 끊는다)
- 학교 폼이 EUC-KR 이라 ASCII 밖의 학번·비밀번호는 보낼 수 없다(400)
